# تحویل فروشگاه با اولویت مرورگر دسکتاپ

## دامنهٔ نسخهٔ اول

فروشگاه و پنل مدیریت در مرورگر دسکتاپ مسیر اصلی تحویل هستند. اپ مستقل ویندوز، Android و iOS و آزمون دستگاه فیزیکی، مانع لانچ وب نیستند. Docker یک گزینهٔ استقرار است و برای اجرای محلی لازم نیست.

## اجرای ویندوز

پیش‌نیاز یک‌باره: PowerShell 7.4 یا جدیدتر، .NET SDK 10، Node.js 22 LTS، Git و Flutter 3.44.7 روی PATH. Flutter برای ساخت پنل وب استفاده می‌شود؛ نصب Android Studio یا ابزار ساخت اپ موبایل لازم نیست.

1. روی ویندوز تازه، مخزن را دریافت کنید و `Mazeduneh.ps1` را با PowerShell اجرا کنید؛ `setup-local.cmd` و `start-local.cmd` هم فقط به همین راه‌انداز ارجاع می‌دهند. پیش‌نیازهای مفقود بررسی و از winget و Flutter از مخزن رسمی دریافت می‌شوند؛ ممکن است نصب‌کننده اجازهٔ مدیریت ویندوز بخواهد. پس از نصب اولیه، `Mazeduneh.ps1` یا میان‌بر دسکتاپ کافی است. SQL Server لازم نیست. نصب خودکار به Windows با Microsoft App Installer نیاز دارد؛ این راه‌انداز مخصوص ویندوز است.
2. بار اول وابستگی‌ها و PostgreSQL قابل حمل از وب‌سایت رسمی EDB دریافت و ساخت انجام می‌شود؛ اینترنت و فضای خالی لازم است. دریافت وابستگی‌های پنل با آینه‌های جایگزین و تلاش مجدد انجام می‌شود تا آدرس سراسری Pub که ممکن است محدود شده باشد راه‌اندازی را متوقف نکند. برای شبکه‌ای با آینهٔ اختصاصی، `MAZEDUNEH_PUB_HOSTED_URL` و `MAZEDUNEH_FLUTTER_STORAGE_BASE_URL` را پیش از اجرا تنظیم کنید. اجراهای بعدی از کش استفاده می‌کنند.
3. پورت‌های پیش‌فرض فروشگاه، پنل و API به‌ترتیب 3000، 8080 و 5080 هستند. اگر پورت اشغال باشد، برنامه پورت آزاد بعدی را انتخاب و نشانی نهایی را در ترمینال نشان می‌دهد؛ برنامهٔ ناشناس را نمی‌بندد. اجرای دوبارهٔ همان checkout نشست سالم را بازاستفاده می‌کند و checkout جداگانه روی پورت‌های آزاد خودش بالا می‌آید. سلامت واقعی API و دیتابیس در `/health/ready` روی پورت API انتخاب‌شده بررسی می‌شود.
4. نام کاربری و رمز محلی در `%LOCALAPPDATA%/Mazeduneh/local/credentials.json` ذخیره می‌شوند. این فایل خصوصی است؛ وارد مخزن نکنید.

داده‌ها با توقف برنامه باقی می‌مانند. اسکریپت روی مخزن fetch/reset انجام نمی‌دهد. نمونه کالاها فقط در دیتابیس محلی خالی ایجاد می‌شوند. پرداخت محلی آزمایشی است؛ برای تکمیل از دکمهٔ مشخص آزمایشی در رسید استفاده کنید.

```powershell
./Mazeduneh.ps1 -Action status
./Mazeduneh.ps1 -Action stop
./Mazeduneh.ps1 -Action restart
./scripts/install-desktop-shortcuts.ps1
# برای درایو دیگری با فضای بیشتر، در همهٔ اجراها همین مسیرها را بدهید:
./Mazeduneh.ps1 -LocalHome D:/Mazeduneh/local -RuntimeHome D:/Mazeduneh/runtime
./scripts/install-desktop-shortcuts.ps1 -LocalHome D:/Mazeduneh/local -RuntimeHome D:/Mazeduneh/runtime
```

پس از تغییر کد، توقف و شروع مجدد ساخت را به‌روز می‌کند. `-SkipBuild` تنها برای ساخت موفق قبلی است. گزارش خطاها در پوشهٔ داده قرار دارد. برای تغییر وابستگی‌های Flutter، داخل `apps/admin` دستور `flutter pub get` را اجرا کنید. حذف پوشهٔ postgres-data داده‌ها را از بین می‌برد؛ برای رفع خطا آن را پاک نکنید.

## دیتابیس و انتقال به سرور

پیاده‌سازی فعلی از PostgreSQL، Npgsql و مهاجرت‌های اختصاصی PostgreSQL استفاده می‌کند. نسخهٔ قابل حمل محلی روی پورت 55432 تنها به loopback گوش می‌دهد. وجود SQL Server لازم نیست؛ اگر نصب باشد نیز تغییری در آن ایجاد نمی‌شود. تبدیل به SQL Server در این مرحله توسعهٔ جداگانه و آزمون همهٔ تراکنش‌ها را می‌خواهد و اجرای محلی را ساده‌تر نمی‌کند.

روی سرور نیز PostgreSQL با همین schema استفاده شود. دادهٔ تست و credentials محلی به محیط واقعی منتقل نشوند. اجرای محلی معیار آمادگی تولید نیست.

## ترتیب کار و پذیرش

1. راه‌اندازی بدون Docker و بررسی پاسخ JSON آمادهٔ API و اتصال دیتابیس.
2. کوپن درصدی، مبلغ ثابت و ارسال رایگان: بازهٔ زمانی، حداقل سبد، سقف مبلغ/مصرف، دامنهٔ SKU، پیش‌نمایش سود، تأیید زیان فقط توسط Owner، ثبت تخفیف در سفارش و فاکتور. هر سفارش یک کوپن؛ پیش‌نمایش رزرو موجودی یا مصرف نیست.
3. آزمون مرورگری خرید و پرداخت آزمایشی، سفارش پنل، فاکتور، مجوزها، کیبورد و خطاهای فرم؛ تأیید صاحب فروشگاه.
4. پس از تأیید، محیط staging روی سرور: PostgreSQL، API منتشرشده با `dotnet publish`، خروجی تولیدی Next (`npm ci`, `npm run build`, `npm run start`)، خروجی Flutter وب پشت وب‌سرور، HTTPS و مبدأهای مجاز مشخص.
5. پیش از سرویس API، اجرای همان DLL با `--migrate` و در نصب نخست `--seed-admin`؛ از `--seed-demo` در سرور واقعی استفاده نشود. اتصال دیتابیس و کلیدها از secret محیط سرور، Sandbox خاموش، MFA روشن، درگاه و callback واقعی تنظیم شوند. جزئیات تنظیم تولید در راهنماهای موجود deployment حفظ شده‌اند.
6. بازیابی بکاپ روی دیتابیس جدا، خرید واقعی کنترل‌شده و تطبیق سفارش/پرداخت، پایش و برنامهٔ برگشت؛ سپس تصمیم لانچ.

پک، خرید X و هدیه Y، محدودیت مشتری/شهر/دسته، خرید اول و کمپین خودکار پیاده‌سازی شده‌اند؛ راهنمای کاربرد و سیاست تعارض در [PROMOTIONS.md](PROMOTIONS.md) است. هر سفارش یک تخفیف دارد و stacking مجاز نیست. پذیرش مالک و بررسی staging دروازهٔ جداگانهٔ لانچ‌اند؛ تست اپ‌های مستقل به فاز بعد از وب منتقل شده است.
