# ثبت تصمیم — ماندگاری کاتالوگ در PostgreSQL

## مسئله
کاتالوگ قبلی فقط در حافظه API قرار داشت. با Restart همه محصولاتی که مدیر ایجاد می‌کرد از بین می‌رفتند و فروشگاه نمی‌توانست منبع داده قابل اتکایی داشته باشد.

## معیار پذیرش
- اجرای PostgreSQL محلی با یک فرمان
- ساخت idempotent جدول‌ها در شروع API
- ماندگاری محصول و Variant پس از Restart
- یکتایی Slug و SKU در دیتابیس
- ادامه کار API در محیط‌های بدون Connection String
- جلوگیری از ثبت محصول نیمه‌کاره در حافظه در صورت شکست تراکنش دیتابیس

## گزینه‌ها
1. ایجاد پروژه Supabase جدید: رد شد؛ ظرفیت حساب فعلی پر است و وابستگی اضافه ایجاد می‌کند.
2. ذخیره JSON روی دیسک: رد شد؛ برای همزمانی، مهاجرت و گزارش‌گیری مناسب فروشگاه نیست.
3. PostgreSQL مستقل: انتخاب شد؛ استاندارد، قابل انتقال و سازگار با مسیر هاست آینده است.

## نظر میزگرد
- مدیر محصول: ثبت محصول باید از همین مرحله ماندگار باشد تا پنل نمایشی باقی نماند.
- مدیر فنی: API نباید به یک سرویس‌دهنده خاص قفل شود.
- ASP.NET Core: تراکنش درج Product و Variantها باید یکپارچه باشد.
- Next.js و Flutter: قرارداد JSON فعلی حفظ شود تا اتصال رابط‌ها نشکند.
- QA: خطای یکتایی باید Conflict کنترل‌شده بدهد، نه خطای 500.
- انباردار: موجودی روی Variant و بر حسب تعداد بسته قابل فروش باقی بماند.
- حسابدار: قیمت فعلاً روی Variant است؛ هزینه خرید و Batch در برش انبار اضافه می‌شود.
- متخصص خشکبار: مبدأ و دسته حفظ شده؛ درجه، فرآوری، آلرژن و تاریخ بسته‌بندی در برش بعدی لازم است.
- UI/UX و فروش: هنوز باید فرم Flutter به API متصل و حالت خطا/بارگذاری اضافه شود.

## تصمیم
از PostgreSQL 17 برای توسعه محلی استفاده می‌شود. API با Npgsql و SQL صریح، schema را بدون تخریب داده ایجاد می‌کند. اگر Connection String موجود باشد، داده‌ها از دیتابیس Hydrate می‌شوند؛ در غیر این صورت رفتار حافظه‌ای قبلی برای Previewهای فاقد Backend حفظ می‌شود.

## کنترل یکپارچگی
- Product و Variantها در یک Transaction درج می‌شوند.
- Slug و SKU در دیتابیس Unique هستند.
- Quantity، Price و Stock دارای Check Constraint هستند.
- محصول فقط بعد از Commit موفق به حافظه اضافه می‌شود.

## اجرای محلی
```bash
docker compose up -d postgres
ConnectionStrings__Catalog='Host=localhost;Port=5432;Database=mazeduneh;Username=mazeduneh;Password=mazeduneh_local_only' dotnet run --project services/api
```

رمز داخل compose فقط برای توسعه محلی است و در Production استفاده نمی‌شود.

## ریسک باقی‌مانده
- Migration نسخه‌بندی‌شده هنوز جایگزین schema bootstrap نشده است.
- Authentication پنل هنوز فعال نیست.
- اتصال Flutter و Storefront به API در برش بعدی انجام می‌شود.
- Backup و Restore Drill پیش از انتشار واقعی الزامی است.
