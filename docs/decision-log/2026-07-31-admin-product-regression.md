# لاگ تصمیم — بازگردانی مدیریت کامل محصول

## مسئله

پس از اضافه‌شدن داشبورد و عملیات سفارش، صفحه محصولات به نمای فقط‌خواندنی تبدیل شده بود و مسیر قبلی افزودن محصول و انتشار از UI حذف شد. Backend و Client همچنان این قابلیت‌ها را داشتند، اما مدیر از پنل جدید به آن‌ها دسترسی نداشت.

## نظر میزگرد

- **مدیر محصول:** اضافه‌شدن قابلیت جدید نباید قابلیت قبلی را حذف کند؛ این یک Regression انتشار بود.
- **فروش و بازاریابی:** محصول ناقص نباید مستقیم در سایت عمومی نمایش داده شود.
- **انباردار:** موجودی باید برای هر بسته مستقل ثبت شود، نه فقط روی عنوان کلی کالا.
- **حسابدار:** ورودی قیمت در پنل برای مدیر به تومان است، ولی قرارداد Backend به ریال باقی می‌ماند؛ تبدیل باید صریح و فقط یک‌بار انجام شود.
- **متخصص خشکبار:** محصولات وزنی باید بسته‌های ۲۵۰، ۵۰۰ و ۱۰۰۰ گرم را سریع بسازند و محصولات عددی پک‌های چندتایی را پشتیبانی کنند.
- **QA:** ثبت محصول سه‌Variant، Draft پیش‌فرض، Bearer Token و انتشار جداگانه باید Gate باشند.

## تصمیم و اصلاح

- صفحه Product Management مستقل ساخته شد و دوباره داخل Shell عملیاتی قرار گرفت.
- فرم تمام‌صفحه Responsive برای محصولات وزنی و عددی اضافه شد.
- بسته‌های پیش‌فرض وزنی و عددی قابل ویرایش، حذف و افزایش هستند.
- هر Variant دارای SKU، مقدار، عنوان، قیمت فروش و موجودی مستقل است.
- محصول جدید همیشه Draft ایجاد می‌شود.
- انتشار یا خروج از فروش نیازمند تأیید صریح است.
- قیمت واردشده به تومان پیش از ارسال به Backend به ریال تبدیل می‌شود.
- داشبورد و سفارش‌ها بدون حذف یا تضعیف باقی ماندند.

## گیت تست

- Flutter Analyze و Tests
- Contract test برای محصول Draft با سه Variant
- Bearer Token در درخواست ثبت محصول
- Flutter Web و Android APK
- API/PostgreSQL و Storefront بدون Regression

## ریسک باقی‌مانده

- ویرایش مشخصات و Variantهای محصول موجود هنوز Endpoint مستقل ندارد.
- تصویر، اطلاعات آلرژن، فرآوری، درجه کیفیت و شرایط نگهداری باید به مدل محصول اضافه شوند.
- ورود موجودی مبتنی بر Batch هنوز در برش انبار تکمیل نشده است.
