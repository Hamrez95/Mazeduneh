# لاگ تصمیم — ورود امن مالک و حفاظت از API مدیریتی

تاریخ: ۱۴۰۵/۰۵/۰۹

## مسئله

مسیرهای دریافت کاتالوگ مدیریتی، ایجاد محصول و تغییر انتشار بدون احراز هویت بودند. انتشار API در این وضعیت می‌توانست اجازه مشاهده Draftها یا تغییر فروش محصولات را به کاربر غیرمجاز بدهد.

## معیار پذیرش

- مسیرهای مدیریتی بدون Bearer Token معتبر پاسخ 401 بدهند.
- ورود مالک بیش از پنج تلاش در دقیقه را نپذیرد.
- Access Token کوتاه‌عمر، امضاشده و غیرقابل تغییر باشد.
- ایمیل، Hash رمز و کلید امضا فقط از Environment دریافت شوند.
- وضعیت پیکربندی احراز هویت در Health Check بدون افشای Secret مشخص باشد.
- مسیرهای عمومی فروشگاه بدون Login باقی بمانند.

## گزینه‌ها

1. API Key ثابت: ساده، اما فاقد انقضا و مناسب نبودن برای اپ موبایل.
2. سرویس هویت خارجی: مناسب آینده، اما در این مرحله هزینه و وابستگی اضافی ایجاد می‌کرد.
3. Token امضاشده کوتاه‌عمر با Owner Bootstrap: انتخاب فعلی.

## تصمیم

ورود اولیه Owner با ایمیل و Hash رمز محیطی انجام می‌شود. API یک Token امضاشده با HMAC-SHA256 و عمر پیش‌فرض ۱۵ دقیقه صادر می‌کند. مسیرهای مدیریتی با Endpoint Filter محافظت می‌شوند. Login نیز Fixed Window Rate Limit دارد.

## تنظیمات محیطی

```text
Admin__Email=owner@example.com
Admin__PasswordHash=<SHA-256 password as 64 hex characters>
Admin__TokenSigningKey=<random secret with at least 32 characters>
Admin__AccessTokenMinutes=15
```

ساخت Hash توسعه محلی:

```bash
printf '%s' 'your-password' | sha256sum
```

رمز خام یا کلید امضا نباید وارد Git، Log یا Flutter Build شود.

## نظر میزگرد

- مدیر محصول و فروش: Draft و انتشار باید فقط در دست مالک باشد.
- مدیر فنی: Token کوتاه‌عمر از API Key ثابت امن‌تر است و بدون سرویس پولی قابل اجراست.
- Backend: مقایسه Hash و Signature به‌صورت Fixed Time انجام می‌شود.
- Flutter: مرحله بعد باید Login Screen و نگهداری امن Session را اضافه کند.
- QA: 401، رمز اشتباه، Token دستکاری‌شده، Token منقضی و 429 باید تست شوند.
- حسابدار و انباردار: تغییرات مالی و موجودی در آینده به Role و Audit قوی‌تر نیاز دارند.
- متخصص خشکبار: توقف فروش کالای مشکوک باید فقط برای نقش مجاز ممکن باشد.
- UI/UX: خطای ورود نباید مشخص کند ایمیل یا رمز کدام‌یک اشتباه است.

## محدودیت و گام بعد

این برش فقط نقش Owner دارد. MFA، Refresh Token، لغو Session، نقش‌های کارکنان و Audit Log دائمی در Sliceهای بعدی اضافه می‌شوند. تا آن زمان API مدیریتی نباید بدون TLS و Secrets واقعی عمومی شود.
