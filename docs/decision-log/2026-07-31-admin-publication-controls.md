# کنترل انتشار محصول در پنل مدیریت

## مسئله

API امکان نگهداری محصول به‌صورت پیش‌نویس و تغییر وضعیت انتشار را داشت، اما پنل Flutter فقط محصولات عمومی را می‌خواند و مدیر راهی برای مشاهده Draftها، انتشار محصول یا خروج امن آن از فروش نداشت. همچنین محصول جدید به‌صورت پیش‌فرض منتشر می‌شد و احتمال نمایش اطلاعات ناقص در فروشگاه وجود داشت.

## معیار پذیرش

- پنل همه محصولات مدیریتی، شامل پیش‌نویس‌ها را دریافت کند.
- وضعیت انتشار هر محصول به‌صورت واضح و غیررنگی نیز قابل تشخیص باشد.
- تغییر وضعیت بدون تأیید صریح انجام نشود.
- هنگام درخواست، کنترل همان محصول غیرفعال و وضعیت انتظار نمایش داده شود.
- خطای API باعث تغییر خوش‌بینانه و نادرست UI نشود.
- پس از موفقیت، کاتالوگ از سرور دوباره خوانده شود.
- محصول جدید به‌صورت پیش‌نویس ایجاد شود.

## گزینه‌ها

1. حذف محصول از فروش: رد شد؛ سابقه محصول و ارتباط آینده با سفارش و انبار نباید از بین برود.
2. تغییر فوری با Switch بدون تأیید: رد شد؛ لمس اشتباه روی موبایل می‌تواند محصول فعال را مخفی کند.
3. تغییر وضعیت با تأیید، Loading و Refresh از سرور: انتخاب شد.

## نظر میزگرد

- مدیر محصول و فروش: Draft باید در پنل دیده شود ولی هرگز وارد کاتالوگ عمومی نشود.
- مدیر فنی و Backend: حقیقت وضعیت در API و PostgreSQL باقی می‌ماند؛ UI پس از تغییر دوباره داده را می‌خواند.
- Flutter و UI/UX: Badge متنی، دکمه عملیاتی و Dialog تأیید برای موبایل واضح‌تر از Switch تنها هستند.
- QA: درخواست PATCH، مسیر admin و پیش‌فرض Draft باید تست شوند.
- انباردار: خروج از فروش نباید موجودی و سابقه کالا را حذف کند.
- حسابدار: حفظ شناسه محصول برای گزارش‌های آتی ضروری است.
- متخصص خشکبار: امکان توقف فوری فروش برای کالای مشکوک، منقضی یا مردود کیفی لازم است.
- بازاریابی و گرافیک: وضعیت داخلی Draft نباید در Storefront یا محتوای تبلیغاتی ظاهر شود.

## تصمیم

پنل از `GET /api/v1/products/admin` استفاده می‌کند. هر کارت محصول Badge متنی «منتشرشده» یا «پیش‌نویس» دارد. عملیات انتشار و خروج از فروش با Dialog تأیید، Loading اختصاصی و `PATCH /api/v1/products/{slug}/publication` انجام می‌شود. پس از موفقیت، کل فهرست از سرور Refresh می‌شود. محصولات جدید با `isPublished=false` ایجاد می‌شوند.

## ریسک باقی‌مانده

مسیرهای مدیریتی هنوز احراز هویت و مجوز نقش ندارند؛ بنابراین API عمومی Production تا پیاده‌سازی Authentication، Authorization و Audit Log منتشر نمی‌شود.
