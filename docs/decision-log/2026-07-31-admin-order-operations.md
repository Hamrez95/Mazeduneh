# لاگ تصمیم — داشبورد و عملیات سفارش مدیر

## مسئله

سفارش و پرداخت در PostgreSQL ماندگار شده بودند، اما پنل مدیر فقط کاتالوگ را نمایش می‌داد و شاخص‌های داشبورد نمونه بودند. مدیر امکان مشاهده سفارش، پیگیری وضعیت، ثبت ارسال یا مشاهده فروش واقعی را نداشت.

## نظر میزگرد

- **مدیر محصول و فروش:** اولین صفحه باید فروش امروز، سفارش‌های نیازمند اقدام و وضعیت ارسال را نشان دهد.
- **انباردار:** لغو سفارش پرداخت‌نشده باید موجودی رزروشده را در همان تراکنش آزاد کند.
- **حسابدار:** سفارش پرداخت‌شده نباید با دکمه لغو ساده برگشت بخورد؛ Refund و سند مالی باید جریان جدا داشته باشند.
- **مدیر فنی:** انتقال وضعیت باید State Machine محدود داشته باشد و هر Transition ماندگار شود.
- **Flutter/UI:** یک کد برای Android و PWA با Navigation Bar موبایل و Navigation Rail دسکتاپ استفاده شود.
- **امنیت:** فهرست سفارش، گزارش و تغییر وضعیت همگی فقط با Bearer Token مالک قابل دسترس باشند.
- **QA:** مسیر Paid → Preparing → Shipped → Delivered، عدم دسترسی بدون Token و ماندگاری بعد از Restart باید در PostgreSQL واقعی تست شوند.

## تصمیم

- Endpointهای محافظت‌شده برای فهرست سفارش، داشبورد و تغییر وضعیت اضافه شدند.
- State Machine مجاز:
  - AwaitingPayment → Cancelled
  - Paid → Preparing
  - Preparing → Shipped
  - Shipped → Delivered
- لغو AwaitingPayment موجودی را آزاد می‌کند و تاریخچه ثبت می‌شود.
- داشبورد از داده واقعی فروش و موجودی ساخته می‌شود؛ عدد نمونه حذف شد.
- پنل سه بخش Dashboard، Orders و Products دارد.
- وضعیت‌ها با متن فارسی، اقدام بعدی روشن و تأیید قبل از تغییر نمایش داده می‌شوند.
- Client Flutter در 401 نشست را پاک می‌کند و کاربر را به Login بازمی‌گرداند.

## گیت تست

- ورود با حساب CI و دریافت Bearer Token
- رد دسترسی بدون Token
- مشاهده سفارش Paid و مرجع پرداخت
- انتقال پیاپی Preparing، Shipped و Delivered
- بررسی درآمد و Delivered در داشبورد
- Restart API و بررسی تاریخچه کامل سفارش
- Flutter Client tests برای Header، Parsing، PATCH و 401
- Build کامل API، Storefront، Flutter Web و APK

## ریسک باقی‌مانده

- Refund سفارش پرداخت‌شده هنوز پیاده نشده و عمداً در UI وجود ندارد.
- کد رهگیری پستی، شرکت حمل و زمان تحویل باید به مرحله Shipped افزوده شوند.
- صفحه جزئیات کامل سفارش و چاپ لیبل بسته‌بندی در برش بعدی تکمیل می‌شوند.
- نقش‌های جداگانه فروش، انبار و حسابداری هنوز به Owner محدود هستند.
