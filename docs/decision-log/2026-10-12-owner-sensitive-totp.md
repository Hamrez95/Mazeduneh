# تأیید دومرحله‌ای برای عملیات حساس Owner

## تصمیم

کد TOTP برای ورود روزمرهٔ پنل درخواست نمی‌شود. API فقط در endpoint تأیید دوبارهٔ هویت و فقط برای نقش `Owner`، پس از اعتبارسنجی رمز عبور، کد شش‌رقمی TOTP را بررسی می‌کند. نقش‌های عملیاتی غیر Owner همان تأیید رمز عبور را دارند. عملیات حساس تا وقتی secret سروری معتبر پیکربندی نشده باشد fail closed است.

کد با RFC 6238، SHA-1، بازهٔ ۳۰ ثانیه و یک رقم در هر طرف برای اختلاف محدود ساعت اعتبارسنجی می‌شود. زمان کد پذیرفته‌شده با upsert اتمیک در PostgreSQL ثبت می‌شود تا در چند درخواست یا replica دوباره مصرف نشود. پس از تأیید، API proof امضاشده با انقضای حداکثر پنج دقیقه می‌دهد؛ پنل آن را فقط در حافظهٔ نشست نگه می‌دارد و با خروج، تغییر هویت یا پایان اعتبار پاک می‌کند.

## تجربهٔ مشتری

این Slice فقط API و پنل مدیریتی را تغییر می‌دهد. مسیر ورود مشتری، پروفایل مشتری و ثبت/پرداخت سفارش هیچ فیلد MFA یا مرحلهٔ تازه‌ای دریافت نمی‌کند.

## راه‌اندازی

برای API مقدار `Admin__Mfa__OwnerTotpSecret` را به‌عنوان secret Base32 تصادفی حداقل ۲۰ بایتی در Secret Manager قرار دهید و همان مقدار را در اپلیکیشن authenticator Owner ثبت کنید. محیط توسعهٔ محلی secret جداگانه‌ای در `.local-dev/admin-totp-secret.txt` نگه می‌دارد و URI ثبت اولیه را فقط در همان اجرای محلی نشان می‌دهد. secret نمونهٔ CI صرفاً برای تست است و نباید برای محیط واقعی استفاده شود.

## موارد باقی‌مانده در #91

- ثبت و بازیابی MFA به‌ازای عضویت هر مدیر و به‌جای یک secret مشترک Owner.
- لغو امن MFA و کدهای بازیابی.
- آزمون یکپارچهٔ replay guard روی PostgreSQL در CI.
- بازبینی جامع IDOR و چرخهٔ عمر نشست‌ها برای تمام endpointهای مدیریتی.
