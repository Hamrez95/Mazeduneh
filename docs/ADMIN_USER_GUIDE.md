# راهنمای استفاده از پنل مدیریت مزه‌دونه

> این راهنما بر اساس وضعیت واقعی main نوشته شده است. مسیرهایی که هنوز کامل نشده‌اند با «در Roadmap» مشخص شده‌اند و نباید به‌عنوان قابلیت آمادهٔ تولید فرض شوند.

## شروع کار

1. از صفحهٔ ورود پنل وارد شوید.
2. بعد از ورود، نام فروشگاه و نقش خود را بررسی کنید.
3. داشبورد باید بخش «امروز چه کاری انجام دهم؟» و Quick Actionها را نشان دهد.
4. اگر صفحه loading، error یا forbidden دیدید، پیام را بخوانید و از همان صفحه Retry یا لینک راهنمای بعدی را انتخاب کنید.
5. در محیط واقعی هیچ رمز، token یا secret را در Issue، Screenshot یا گزارش قرار ندهید.

## داشبورد عملیاتی

مسیر: داشبورد ← بازهٔ فروش ← مشاهدهٔ KPI یا مسیر سریع

1. بازهٔ «امروز»، «۷ روز» یا «۳۰ روز» را انتخاب کنید؛ فروش، تعداد سفارش و میانگین ارزش سفارش از API و همان بازهٔ انتخابی دوباره محاسبه می‌شوند.
2. کارت‌های وضعیت سفارش را برای صف در انتظار پرداخت، آماده‌سازی و ارسال بخوانید.
3. از مسیرهای سریع وارد ثبت محصول، سفارش‌ها، اصلاح موجودی یا فروش سازمانی شوید؛ بعد از انجام کار به ماژول مقصد می‌روید.
4. اگر نوار stale یا خطا دیده شد، از Retry استفاده کنید و اعداد قبلی را به‌عنوان دادهٔ قطعی در نظر نگیرید.

## خروج امن از پنل

مسیر: دکمهٔ خروج امن در نوار کناری دسکتاپ یا نوار بالای موبایل

با انتخاب خروج، token فعلی در API revoke و session محلی پاک می‌شود. پیام موفقیت نمایش داده می‌شود؛ اگر ارتباط قطع باشد، session محلی در هر حال پاک می‌شود و برای ورود دوباره باید به صفحهٔ ورود برگردید.

## مشاهدهٔ Audit عملیات حساس

مسیر API مدیریتی: `GET /api/v1/admin/audit-log` با فیلتر `entityType` و `entityId`

انتشار یا خارج‌کردن محصول از فروش و اصلاح موجودی با actor، زمان، شناسهٔ درخواست، دلیل و snapshot قبل/بعد ثبت می‌شوند. این endpoint فعلاً برای Owner و مصرف داخلی پنل است؛ نمایش کامل جدول Audit و فیلترهای کاربری در ادامهٔ Issue #91 اضافه می‌شود.

| Corporate Sales | درخواست‌های سازمانی، package، follow-up و proforma |
| Content Manager | محصول از نظر متن/media، Home، FAQ، SEO و صفحات محتوا |

## ثبت محصول

مسیر: محصولات ← افزودن محصول

1. عنوان فارسی و slug یکتا را وارد کنید.
2. دسته‌بندی، مبدأ، واحد فروش و توضیح کوتاه را ثبت کنید.
3. حداقل یک variant قابل فروش بسازید.
4. برای هر variant، SKU یکتا، وزن یا تعداد، label، قیمت فروش، موجودی و در صورت نیاز قیمت خرید را ثبت کنید.
5. اطلاعات مواد تشکیل‌دهنده، آلرژن، ارزش غذایی، کالری، روش نگهداری و ماندگاری را تکمیل کنید.
6. SEO Title و SEO Description را بازبینی کنید.
7. محصول را ذخیره کنید؛ پیام موفقیت باید لینک «مشاهده محصول» و «افزودن تصویر» داشته باشد.
8. اگر اطلاعات اجباری ناقص است، فرم باید دقیقاً همان فیلد را توضیح دهد.

نکته: قیمت، موجودی و وضعیت انتشار از API معتبر هستند؛ عددی که صرفاً در فرم دیده می‌شود منبع نهایی نیست.

## افزودن و مدیریت تصویر

مسیر: محصولات ← انتخاب محصول ← رسانه

1. «افزودن تصویر» را بزنید.
2. فایل مجاز را انتخاب کنید و منتظر upload success بمانید.
3. برای هر تصویر متن جایگزین توصیفی بنویسید.
4. تصویر اصلی را مشخص کنید.
5. ترتیب gallery را بررسی کنید.
6. preview محصول را ببینید تا تصویر از قاب بیرون نزند.
7. اگر رسانه خراب یا گم‌شده است، از Media Library یا همان محصول آن را جایگزین کنید.

در وضعیت فعلی provider رسانه abstraction دارد؛ برای production باید credential و bucket واقعی در محیط امن تنظیم شده باشد. secret را در پنل یا Issue وارد نکنید.

## پیش‌نمایش و انتشار محصول

مسیر: محصولات ← محصول ← پیش‌نمایش ← انتشار

1. پیش‌نمایش desktop و mobile را بررسی کنید.
2. عنوان، gallery، variant، قیمت، موجودی، مواد و نحوهٔ نگهداری را بخوانید.
3. اگر محصول ناقص است، به فرم ویرایش برگردید.
4. برای انتشار، همهٔ بسته‌ها باید SKU، عنوان بسته و قیمت بیشتر از صفر داشته باشند؛ tooltip کنار دکمه این شرط را یادآوری می‌کند.
5. انتشار را با confirmation انجام دهید.
6. بعد از موفقیت، لینک محصول public را باز کنید.
7. برای خارج کردن از فروش، «خارج کردن از انتشار» را بزنید؛ حذف اطلاعات مالی یا سفارش‌های قدیمی مجاز نیست.

محصول draft یا خارج‌شده نباید در Storefront عمومی دیده شود.

## دریافت موجودی

مسیر: انبار ← موجودی ← دریافت کالا

1. SKU و محصول را انتخاب کنید.
2. تأمین‌کننده و در صورت وجود شمارهٔ فاکتور خرید را انتخاب/ثبت کنید.
3. کد batch، مقدار، تاریخ تولید و تاریخ انقضا را وارد کنید.
4. قیمت خرید، هزینهٔ بسته‌بندی و هزینهٔ جانبی را ثبت کنید.
5. صحت تاریخ و مقدار را بررسی کنید.
6. دریافت را تأیید کنید.
7. سیستم باید movement و balance جدید را نشان دهد.

هر دریافت، اصلاح، فروش، رزرو، release، برگشت و ضایعات باید در ledger ثبت شود.

## بررسی تاریخ انقضا و FEFO

مسیر: انبار ← نزدیک به انقضا

1. نوار هشدار بالای صفحهٔ انبار را بررسی کنید؛ تعداد بچ منقضی و بچی که تا ۳۰ روز آینده منقضی می‌شود جدا نمایش داده می‌شود.
2. در فهرست بچ‌ها، موارد «منقضی شده» یا «نزدیک انقضا» را اول بررسی کنید.
3. ابتدا batch با تاریخ نزدیک‌تر را برای سفارش آماده کنید؛ این همان راهنمای FEFO است.
4. batch منقضی نباید قابل فروش یا رزرو باشد.
5. اگر batch مشکل دارد، دلیل اصلاح/ضایعات را ثبت کنید.
6. پس از بررسی، با دکمهٔ دریافت بچ یا اصلاح موجودی اقدام بعدی را انجام دهید و گردش جدید را کنترل کنید.

## اصلاح موجودی

مسیر: انبار ← SKU ← اصلاح موجودی

1. مقدار تغییر را وارد کنید.
2. دلیل واقعی را انتخاب/توضیح دهید.
3. قبل و بعد را بررسی کنید.
4. تأیید صریح را انجام دهید.
5. movement، actor و زمان را در تاریخچه ببینید.

اصلاح موجودی بدون دلیل، actor یا permission مجاز نیست.

## پیگیری سفارش

مسیر: سفارش‌ها ← جست‌وجو و فیلتر

فیلترهای اصلی: وضعیت، تاریخ، مبلغ، شهر، مشتری، روش ارسال و سفارش مشکل‌دار.

1. سفارش را باز کنید.
2. در summary مشتری، آدرس، اقلام، variant، مبلغ، تخفیف، مالیات و ارسال را بررسی کنید.
3. Timeline را بخوانید تا مرحلهٔ فعلی مشخص باشد.
4. اقدام بعدی را انجام دهید: تغییر وضعیت، یادداشت داخلی، tracking، آماده‌سازی یا لغو.
5. در عملیات حساس confirmation را تأیید کنید.
6. بعد از موفقیت به صف سفارش‌ها برگردید؛ فیلتر قبلی حفظ شود.

### خروجی سفارش‌ها

مسیر: سفارش‌ها ← اعمال فیلتر ← خروجی CSV

فیلتر وضعیت و عبارت جست‌وجو قبل از خروجی روی فایل اعمال می‌شوند. فایل شامل سفارش، مشتری، شهر، وضعیت، مبلغ، تعداد اقلام و وضعیت پرداخت است و برای بررسی حسابداری یا پیگیری روزانه قابل استفاده است. اطلاعات حساس خارج از سطح دسترسی نقش صادرکننده در خروجی قرار نمی‌گیرد.

### چاپ برگهٔ بسته‌بندی

مسیر: سفارش‌ها ← انتخاب سفارش ← جزئیات ← برگهٔ بسته‌بندی

1. سفارش را باز کنید و اقلام، تعداد و نشانی گیرنده را بررسی کنید.
2. «برگهٔ بسته‌بندی» را بزنید؛ خروجی در صفحهٔ جدید باز می‌شود.
3. اقلام را هنگام جمع‌آوری علامت بزنید و ترتیب FEFO را رعایت کنید.
4. سلامت بسته، تعداد اقلام و آدرس را کنترل کنید.
5. برگه را چاپ کنید یا به PDF ذخیره کنید و سپس سفارش را به مرحلهٔ ارسال ببرید.

اگر صفحهٔ چاپ باز نشد، اجازهٔ بازکردن صفحهٔ جدید مرورگر را فعال و دوباره تلاش کنید. خطای دریافت سفارش باید با Retry یا ارجاع به مدیر سیستم پیگیری شود.

### عملیات گروهی سفارش‌ها

مسیر: سفارش‌ها ← اعمال فیلتر ← انتخاب چند سفارش ← عملیات گروهی

1. ابتدا فهرست را با وضعیت، تاریخ، شهر یا عبارت جست‌وجو محدود کنید تا فقط سفارش‌های مرتبط نمایش داده شوند.
2. چک‌باکس کنار سفارش‌ها را انتخاب کنید و تعداد انتخاب‌شده را در دکمهٔ عملیات گروهی بررسی کنید.
3. وضعیت مقصد را انتخاب و پیام تأیید را بخوانید؛ هر بار حداکثر ۵۰ سفارش قابل پردازش است.
4. سیستم قواعد انتقال هر سفارش را جداگانه بررسی می‌کند. سفارش‌های موفق به وضعیت جدید می‌روند و موارد ناموفق با دلیل در پیام نتیجه گزارش می‌شوند.
5. پس از موفقیت، فهرست سفارش‌ها با همان فیلتر دوباره بارگذاری می‌شود و انتخاب‌های قبلی پاک می‌شوند.

این عملیات برای آماده‌سازی صف سفارش‌ها، انتقال سفارش‌های ارسال‌شده و تحویل‌شده مناسب است. برای اصلاح مبلغ، بازپرداخت یا تغییر حساس، سفارش را جداگانه باز کنید تا تأیید و تاریخچهٔ کامل آن ثبت شود.

مسیر خطای سفارش: سفارش ← payment/stock/shipping problem ← اصلاح ← Retry یا ارجاع به مسئول.

## مشاهدهٔ سود محصول

مسیر پیشنهادی: داشبورد ← Quick Action «پیگیری فروش محصول» ← محصول ← سفارش‌های مرتبط ← بازهٔ زمانی ← گزارش سود

1. محصول یا SKU را انتخاب کنید.
2. بازهٔ زمانی و وضعیت سفارش را مشخص کنید.
3. فروش ناخالص، تخفیف، مالیات، هزینهٔ خرید، بسته‌بندی، هزینهٔ جانبی و ارسال واقعی را بررسی کنید.
4. gross/net profit و margin را بخوانید.
5. از هر عدد به سفارش یا ledger منبع drill-down کنید.
6. اگر سود منفی است، قبل از campaign یا تغییر قیمت هشدار را بررسی کنید.

تعریف کامل net profit و accounting integration در Roadmap و Issue #82 تکمیل می‌شود.

## پیدا کردن مشتری

مسیر: مشتریان ← جست‌وجو ← پروفایل مشتری

1. با نام یا شمارهٔ نرمال‌شده جست‌وجو کنید.
2. مجموع خرید، میانگین ارزش سفارش، آخرین خرید موفق و تعداد سفارش‌ها را ببینید؛ سفارش‌های لغوشده یا منقضی در شاخص مالی حساب نمی‌شوند.
3. آدرس پیش‌فرض و تاریخچهٔ آدرس را بررسی کنید.
4. یادداشت داخلی یا تاریخچهٔ تماس را ثبت کنید.
5. برای خروجی گرفتن، عبارت جست‌وجو را وارد کنید و «خروجی CSV» را بزنید؛ فایل فقط با دسترسی مدیریتی و با همان فیلتر تهیه می‌شود.
6. اطلاعات حساس را فقط در محدودهٔ نقش خود ببینید و فایل خروجی را در اختیار افراد غیرمجاز نگذارید.
7. برای segmentation و customer source/campaign از Issue #94 پیروی کنید.

## ساخت کد تخفیف

مسیر هدف: بازاریابی ← تخفیف‌ها و کمپین‌ها ← ایجاد

نسخهٔ کامل در Roadmap است. در طراحی نهایی این گام‌ها باید وجود داشته باشد:

1. نوع: درصدی، مبلغی، محصول، دسته، شهر، مشتری یا اولین خرید.
2. دامنهٔ محصول و شرط حداقل سفارش.
3. تاریخ شروع/پایان، timezone و سقف مصرف.
4. stack/conflict policy.
5. preview یک سبد واقعی و سود آن.
6. هشدار سود منفی و تأیید Owner در صورت نیاز.
7. انتشار یا زمان‌بندی.
8. گزارش redemption و عملکرد.

قیمت نهایی همیشه توسط API محاسبه می‌شود.

## ایجاد کمپین

مسیر: بازاریابی ← کمپین‌ها

کمپین یلدا، نوروز، سازمانی یا seasonal را با هدف، audience، محصول/دسته، بودجه/شرط، زمان و CTA تعریف کنید. قبل از انتشار preview بگیرید و بعد از پایان، فروش، سود، مصرف کد و نرخ تبدیل را گزارش کنید.

## پیگیری فروش سازمانی

مسیر: فروش سازمانی ← Pipeline ← درخواست

1. درخواست جدید را باز کنید.
2. نام شرکت، شخص تماس، شهر، تعداد، مناسبت، package و تاریخ تحویل را بخوانید.
3. مسئول فروش را تعیین کنید.
4. تاریخ follow-up بعدی را ثبت کنید.
5. تماس، پیام و note را در timeline وارد کنید.
6. package اقتصادی، استاندارد یا پریمیوم را انتخاب و مبلغ را snapshot کنید.
7. پیش‌فاکتور را تولید/بارگذاری کنید.
8. status را از New تا Finalized تغییر دهید.
9. در صورت تبدیل به سفارش، لینک corporate request و order را بررسی کنید.

هیچ درخواست فعال نباید بدون owner یا next follow-up باقی بماند مگر با دلیل.

## گزارش مالی

مسیر: گزارش‌ها ← فروش/هزینه/سود/تسویه

1. گزارش و بازهٔ زمانی را انتخاب کنید.
2. timezone و واحد پول را بررسی کنید.
3. بر اساس محصول، variant، دسته، شهر، مشتری یا campaign فیلتر کنید.
4. سفارش‌های لغو، refund و return را جداگانه بررسی کنید.
5. گزارش را با سفارش نهایی و stock ledger reconcile کنید.
6. خروجی CSV/Excel را فقط با permission مجاز بگیرید.
7. فاکتور مشتری و گزارش داخلی سود دو خروجی جدا هستند؛ cost/profit نباید به مشتری نمایش داده شود.

## مدیریت محتوا

مسیر: محتوا و بازاریابی ← Home/Hero/CTA/FAQ/About/Contact/Footer/SEO

1. draft بسازید.
2. متن فارسی و لینک‌ها را بررسی کنید.
3. preview دسکتاپ و موبایل بگیرید.
4. alt text و SEO/Open Graph را تکمیل کنید.
5. publish کنید.
6. نسخهٔ قبلی و rollback را فقط با permission مجاز انجام دهید.

## اعلان‌ها

مسیر: Notification Center

اعلان باید severity، زمان، رکورد مرتبط و deep link داشته باشد. اعلان کمبود موجودی باید به SKU/batch برسد؛ اعلان سفارش جدید به order؛ اعلان corporate به request. در صورت خطای provider، delivery attempt و retry را بررسی کنید. SMS/Email/webhook فقط بعد از فعال شدن provider و consent معتبر ارسال شود.

## مسیرهای پیشنهادی برای جلوگیری از گم شدن کاربر

- پیگیری فروش محصول: داشبورد ← محصول ← سفارش‌های مرتبط ← سود و موجودی
- بررسی سود سفارش: سفارش ← cost snapshot ← گزارش سود
- کالای نزدیک انقضا: انبار ← expiry ← batch ← FEFO/ضایعات
- درخواست سازمانی: Corporate ← request ← owner ← follow-up ← proforma/order
- اصلاح موجودی: انبار ← SKU ← adjustment ← reason ← ledger
- کمپین: بازاریابی ← campaign ← rule ← profit preview ← publish
- مشتری غیرفعال: مشتریان ← segment ← last purchase ← contact/consent

## حالت‌های استاندارد صفحه

- Loading: ساختار صفحه و progress قابل فهم.
- Empty: توضیح اینکه چرا خالی است، اقدام اصلی و link راهنما.
- Error: علت ساده، retry امن و مسیر تماس.
- Forbidden: توضیح permission بدون افشای اطلاعات حساس.
- Success: نتیجه، toast/inline status و next action.
- Stale: زمان آخرین به‌روزرسانی، refresh و هشدار اینکه داده ممکن است قدیمی باشد.

## نکات ایمنی

- token، password، key و secret را کپی یا share نکنید.
- مبلغ، موجودی و وضعیت پرداخت را از screenshot یا client قطعی فرض نکنید.
- عملیات مالی و destructive را بدون confirmation انجام ندهید.
- هر مغایرت را با order ID، زمان و توضیح ثبت کنید؛ secret یا PII غیرضروری اضافه نکنید.
