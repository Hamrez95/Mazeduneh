# مرکز اعلان‌ها — مسیر پیگیری و بازیابی خطا

Issue: #96. این Slice اعلان تازه، provider، ارسال پیام یا دادهٔ پایدار جدید ایجاد نمی‌کند؛ اعلان‌های فعلی API را به مسیر عملیاتی قابل استفاده وصل می‌کند.

## مسیر کاربر

- ورود از «اعلان‌ها» در منوی اصلی یا «بیشتر» موبایل؛ خلاصهٔ همان اعلان‌ها در داشبورد نمایش داده می‌شود.
- کاربر عنوان، شرح فارسی، تعداد و اقدام بعدی را می‌بیند.
- «مشاهده سفارش‌ها» برای اعلان انتظار پرداخت/سفارش جدید و «مشاهده موجودی» برای کمبود موجودی، صفحهٔ مرتبط را باز می‌کند.
- این اعلان‌ها صف تجمیعی هستند؛ API شناسهٔ رکورد جداگانه ندارد. دکمه به لیست ماژول می‌رود و ادعای بازکردن یک سفارش یا SKU فیلترشده نمی‌کند.
- مسیر مقصد فقط با مجوز مشاهدهٔ همان بخش نمایش داده می‌شود. نوع اعلان ناشناخته، مسیر حدسی ندارد.
- هیچ داده‌ای با دکمهٔ اعلان ذخیره یا اصلاح نمی‌شود. عملیات بعدی از ماژول سفارش/انبار با مجوز و validation سرور انجام می‌شود؛ پس از آن بازگشت از منوی «اعلان‌ها» یا «داشبورد» است.

## stateها

| وضعیت | تجربهٔ کاربر |
| --- | --- |
| بارگذاری اولیه | نشانگر بارگذاری؛ هنوز داده‌ای نمایش داده نمی‌شود |
| بدون اعلان | توضیح می‌دهد هشدارهای سفارش/موجودی اینجا خواهند آمد |
| دریافت موفق | عنوان/شرح با اعداد فارسی و دکمهٔ قابل‌فهم به ماژول مجاز |
| refresh | دادهٔ فعلی می‌ماند و progress نمایش داده می‌شود؛ refresh هم‌زمان غیرفعال است |
| refresh ناموفق یا قطع اتصال | اعلان‌های قبلی با هشدار قدیمی‌بودن و retry حفظ می‌شوند |
| خطای بارگذاری اولیه | پیام action-oriented و امکان تلاش دوباره |
| ۴۰۱/۴۰۳ | دادهٔ قبلی پنهان می‌شود و state خطای نشست/مجوز نمایش داده می‌شود |
| مقصد نامجاز یا نوع ناشناخته | متن اعلان قابل نمایش است؛ دکمهٔ مقصد حدسی/نامجاز وجود ندارد |

نگاشت اعلان به مقصد و فارسی‌سازی متن در component مشترک `AdminNotificationTile` انجام می‌شود و در Dashboard و Notification Center دوباره استفاده می‌شود. Typography و رنگ از theme موجود می‌آید؛ دکمه TextButton استاندارد keyboard/focus و حداقل هدف ۴۴px دارد. متن‌های title/detail همچنان از API هستند.

API/authorization موجود عوض نشده است. این فیلتر UI جای مجوز سرور یا store isolation را نمی‌گیرد. این Slice راه پیگیری سفارش/موجودی را کوتاه می‌کند؛ محاسبهٔ سود و موجودی همچنان در سرور است.

## QA و محدودهٔ باقی‌مانده

تست widget: مسیر سفارش و موجودی، مجوز محدود، نوع ناشناخته، اعداد فارسی، keyboard، عرض ۳۶۰ و متن ۲۰۰٪، loading، empty، error/retry، stale/recovery و پنهان‌کردن cache در forbidden.

استفاده از Skills: frontend-design، uiuxdesigner:accessibility-audit و lifecycle-architecture-review. Graphify version/query/update به‌دلیل نبود executable اجرا نشد؛ targeted search جایگزین شد. Flutter در executor وجود ندارد؛ analyze/test/build و تمام jobهای Storefront/API/Admin باید در CI پاس شوند.

#96 همچنان شامل unread/read پایدار، template، role/store filtering سمت سرور، preference، provider، retry/dead-letter و automation است. لینک دقیق رکورد یا SKU به contract جدید API نیاز دارد و در این Slice حدس زده نشده است.
